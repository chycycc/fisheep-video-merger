## Proposed Changes

### 一、Bug 修复（6 个已确认问题）

#### [FIX] Bug 1：`window.event` 废弃 API（main.js:919）
- **问题**：`deleteTask()` 使用 `window.event.stopPropagation()`，Alpine.js 的 `@click.stop` 已处理，此处冗余且不可靠
- **方案**：删除 `window.event` 逻辑，Alpine.js 已负责阻止冒泡

#### [FIX] Bug 2：`updateMergeStatusBar` 空值检查缺失（main.js:725）
- **问题**：`statusBar`、`statusText`、`statusChunk` 可能为 null，直接调用会 TypeError
- **方案**：添加 `if (statusBar && statusText && statusChunk)` 守卫

#### [FIX] Bug 3：`initDashboardCards` 空值检查缺失（main.js:741）
- **问题**：同 Bug 2，`getElementById` 结果未检查就直接使用
- **方案**：添加空值守卫

#### [FIX] Bug 4：`start_merging` 引用不存在的元素（bridge.py:466-484）
- **问题**：引用 `start-btn` 和 `cancel-btn`，实际 HTML 中只有 `global-start-btn`，合并时按钮状态更新静默失败，用户可重复点击导致重复提交
- **方案**：改为 `global-start-btn`，移除 `cancel-btn` 引用

#### [FIX] Bug 5：共享列表未加锁（bridge.py 多处）
- **问题**：`delete_pending_file`、`clear_queue`、`manual_match`、`auto_match_pending` 修改共享列表时未使用 `self._lock`，与后台扫描线程竞态
- **方案**：统一使用 `self._lock` 保护

#### [FIX] Bug 6：`_add_folders` 中 `muxed_files` 在锁外更新（bridge.py:362-365）
- **问题**：`muxed_files` 的读取和追加在 `with self._lock:` 块之外，竞态条件
- **方案**：移入锁保护块内

### 三、桥接层清理（为未来 UI 重构留余地）

**目标**：将 Python→JS 的 `evaluate_js()` 调用标准化，未来换框架时只改桥接层，不动核心逻辑。

#### [MODIFY] Python→JS 通信标准化
**当前问题**：25 处 `evaluate_js()` 直接拼接 JS 代码字符串，如：
```python
self._evaluate_js_safe("document.getElementById('start-btn').disabled = true")
```
换框架时这些全部要改。

**方案**：改为发送结构化 JSON 消息，前端监听并处理：
```python
# 之前
self._evaluate_js_safe("window.updateTaskProgress(0, 50, '2min', '10MB/s')")

# 之后
self._send_message("task_progress", {"index": 0, "percent": 50, "eta": "2min", "speed": "10MB/s"})
```

前端统一监听：
```javascript
window.addEventListener('bridge-message', (e) => {
    const { type, data } = e.detail;
    switch (type) {
        case 'task_progress': updateTaskProgress(data); break;
        case 'task_status': updateTaskStatus(data); break;
        case 'state_update': handleBackendResponse(data); break;
        // ...
    }
});
```

**涉及的 25 处 `evaluate_js` 调用分类**：
- 任务进度更新（`updateTaskProgress`、`updateTaskStatus`）
- 工具进度更新（`updateToolProgress`）
- 状态同步（`handleBackendResponse`）
- UI 状态更新（按钮禁用/启用、Toast 显示）
- 主题同步（`setAppTheme`）

#### [MODIFY] JS→Python 调用集中管理
**当前问题**：82 处 `callPython()` 分散在各文件中。

**方案**：在 `js/bridge.js` 中定义 API 常量，集中管理所有调用：
```javascript
// js/bridge.js
export const API = {
    ADD_FOLDER: 'add_folder',
    DELETE_TASK: 'delete_task',
    START_MERGING: 'start_merging',
    // ...
};

export function callApi(method, ...args) {
    return callPython(method, ...args);
}
```

#### [NEW] 接口文档
在 `docs/bridge-api.md` 中记录所有 bridge 方法的签名、参数、返回值，作为未来重构的参考。
