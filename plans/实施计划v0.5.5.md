## 一、Pazera 借鉴 — 音频高级设置

### 1. 声道选择
- **说明**：Pazera 支持 单声道(Mono)/立体声(Stereo)/保持原始
- **改动**：
  - `extractor.py`：新增 `channels` 参数（"mono"/"stereo"/"original"）
  - FFmpeg 参数：`-ac 1`（单声道）/ `-ac 2`（立体声）/ 不加（保持原始）
  - `bridge.py`：extract_audio_api 传递 channels 参数
  - `index.html`：音频提取面板新增声道下拉框
- **复杂度**：低

### 2. 采样率选择
- **说明**：Pazera 支持 8000/11025/22050/44100/48000 Hz
- **改动**：
  - `extractor.py`：新增 `sample_rate` 参数
  - FFmpeg 参数：`-ar 44100`（指定采样率）/ 不加（保持原始）
  - `index.html`：音频提取面板新增采样率下拉框
- **复杂度**：低

### 3. 音量调节
- **说明**：Pazera 支持音量增益滑块
- **改动**：
  - `extractor.py`：新增 `volume` 参数（0.5-2.0，默认 1.0）
  - FFmpeg 参数：`-af "volume=1.5"` 音量增益
  - `index.html`：音频提取面板新增音量滑块（0.5x - 2.0x）
- **复杂度**：低

### 4. CBR/VBR 码率模式
- **说明**：Pazera 支持恒定码率(CBR)和可变码率(VBR)
- **改动**：
  - `extractor.py`：新增 `bitrate_mode` 参数（"cbr"/"vbr"）
  - VBR 模式：MP3 用 `-q:a 2`（VBR 质量 0-9），AAC 用 `-vbr on`
  - `index.html`：码率模式切换，VBR 时显示质量等级选择
- **复杂度**：中

### 5. 输入文件信息展示
- **说明**：Pazera 文件列表显示输入文件的编码/码率/声道/采样率
- **改动**：
  - `bridge.py`：`get_file_info(filepath)` API 返回详细音频信息
  - `ffprobe.py`：`get_video_detail` 已有部分，需补充声道/采样率
  - `index.html`：工具表格增加"编码"/"码率"/"声道"/"采样率"列
- **复杂度**：中

### 6. 编码质量预设
- **说明**：快速选择"高质量/中等/低质量"预设
- **改动**：
  - `index.html`：音频提取面板新增预设按钮组
  - 预设映射：
    - 高质量：320kbps / 48000Hz / 立体声
    - 中等：192kbps / 44100Hz / 立体声
    - 低质量：128kbps / 22050Hz / 单声道
- **复杂度**：低

## 三、FFmpeg 性能优化

### 7. 合并加速 — 流复制优化
- **现状**：合并用 `-c copy`（已经是最快的流复制模式）
- **优化**：
  - 确保所有合并操作都用 `-c copy`，不重编码
  - 添加 `-movflags +faststart` 让 MP4 快速可播放
  - 添加 `-fflags +genpts` 修复时间戳问题
- **预期提升**：合并速度已接近理论上限，此项为确认优化
- **复杂度**：低

### 8. 音频提取加速 — 流复制优先
- **现状**：AAC 提取走重编码（为修复时长问题）
- **优化**：
  - 当源格式与目标格式相同时，优先用 `-c:a copy`（流复制，10-100x 快）
  - 仅在需要格式转换时才重编码
  - 流复制后用 `-f mp4` 重新封装修复时长
- **预期提升**：同格式提取速度提升 10-100x
- **复杂度**：中

### 9. 并行任务优化 — 动态调度
- **现状**：`ThreadPoolExecutor` 提交所有任务，全部 futures 立即创建
- **优化**：
  - 改为分批提交：每批 `max_workers` 个任务
  - 上一批完成后再提交下一批，减少内存占用
  - 添加任务优先级（小文件优先，快速释放队列）
- **预期提升**：大批次时内存占用降低，响应更流畅
- **复杂度**：中

### 10. 硬件加速检测
- **说明**：检测 GPU 编码器可用性，自动选择最快路径
- **改动**：
  - `ffmpeg_runner.py`：新增 `detect_hw_accel()` 函数
  - 检测顺序：NVENC → QSV → AMF → 软编码
  - 转换/压缩工具支持 `-c:v h264_nvenc` 等硬件编码器
  - 合并保持 `-c copy`（不需要 GPU）
- **预期提升**：重编码操作速度提升 3-10x（取决于 GPU）
- **复杂度**：高

### 11. 临时文件优化 — 内存管道
- **现状**：AAC 提取写临时文件再转封装
- **优化**：
  - 用 subprocess pipe 直接传递数据，避免磁盘 I/O
  - 或用 `-f mp4 pipe:1` 输出到管道
- **预期提升**：减少一次磁盘读写
- **复杂度**：高

### 12. 预估时间显示
- **说明**：开始前根据文件大小和编码模式预估总耗时
- **改动**：
  - `bridge.py`：合并前计算总输入大小
  - 根据历史速度（流复制 ~500MB/s，重编码 ~50MB/s）预估
  - 前端显示"预计耗时: 约 2 分钟"
- **复杂度**：低

## 四、其他优化

### 13. 批量音频提取优化
- **现状**：逐文件串行提取
- **优化**：
  - 多文件并行提取（ThreadPoolExecutor）
  - 共享 FFmpeg 进程池
- **预期提升**：批量提取速度与并发数成正比
- **复杂度**：中

### 14. 缓存 ffprobe 结果
- **现状**：每次操作都调用 ffprobe
- **优化**：
  - 首次扫描后缓存文件的元数据（大小/时长/编码/码率）
  - 文件未修改时直接读缓存
  - 用 mtime 校验缓存有效性
- **预期提升**：重复操作秒级响应
- **复杂度**：中
